## 2024-06-25 - Avoid array chaining and spread operators with max/min on large datasets in vanilla JS
**Learning:** In a vanilla JS architecture where large historical sessions (e.g. 500k records) are held in memory arrays, using `.map()`, `.filter()`, and `.reduce()` sequentially causes massive GC churn and up to a 10x performance hit. Furthermore, using `Math.max(...array)` crashes outright with "Maximum call stack size exceeded" on these large datasets.
**Action:** Use single-pass `for` loops to calculate aggregates like `sumTime` and `correctCount` manually. Compute extremes (max/min) iteratively instead of using the spread operator on the entire array. When building histograms, use integer-indexed bin arrays inside loops and map to string labels at the end, rather than continually performing string-based property accesses.
