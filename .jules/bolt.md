## 2024-06-01 - Avoid array chaining and spread operators in large arrays
**Learning:** In the vanilla JS architecture, chaining array methods like `.filter().map().reduce()` or `.filter().length` multiple times on large arrays (`this.history`, `this.sessionData`) causes high CPU overhead and unnecessary intermediate array allocations. More importantly, using the spread operator (`...`) with `Math.max(...times)` on large arrays (>100,000 items) directly causes `RangeError: Maximum call stack size exceeded` and crashes the application. Also, for bucketing operations like histograms, using string interpolation and object properties inside the loop is remarkably slower than using integer-indexed arrays.
**Action:** When iterating over potentially large datasets, replace chained array methods with a single-pass `for` loop. When calculating extremes (max/min), iterate manually instead of using spread with `Math.max`/`Math.min`. For binning and histograms, build integer-indexed arrays first and generate string labels only once after the loop.
