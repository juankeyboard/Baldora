## 2024-06-18 - Single-pass loops and spread operator avoidance in large arrays
**Learning:** In the `DataManager` architecture, `history` and `sessionData` arrays can grow very large (100,000+ items). Using `Math.max(...times)` with the spread operator on these arrays causes "Maximum call stack size exceeded" errors. Additionally, chaining array methods like `.filter().map().reduce()` causes massive CPU overhead and garbage collection due to intermediate array allocations. Inside tight loops for binning/histograms, using string interpolation for object properties introduces unnecessary performance penalties.
**Action:** Always use single-pass `for` loops to find array extremes (like max/min) instead of spread operators. Replace multiple array method chains with a single `for` loop that performs calculations (sum, count) in one pass. For binning or bucket counting, use integer-indexed arrays instead of object keys inside the loop, and map to label strings only after the loop completes.
