## 2024-05-24 - Maximum call stack size exceeded in Array spread and single pass iteration
**Learning:** In the DataManager module (`js/data.js`), using the spread operator with `Math.max(...array)` on large arrays (e.g. history datasets) can cause a `Maximum call stack size exceeded` error. Also, relying on chained array functions like `.filter().map().reduce()` causes intermediate array allocations, resulting in significant CPU overhead (up to ~7x-10x slower on 200k+ arrays). String interpolations for object keys inside heavy iteration loops slow down bucketization logic.
**Action:** Always replace spread operators on potentially large arrays with a single-pass `for` loop to find maximums. Opt for traditional `for` loops in place of chained array methods to accumulate data (averages, counts) within a single pass. Use indexed arrays for bucketing instead of object properties with template literal strings, leaving label generation until after the loop completes.
