## 2025-06-11 - Fixed Stack Overflow in getResponseTimeDistribution
**Learning:** In vanilla JS architectures, using `Math.max(...array)` with the spread operator on large data arrays (like `history` in `DataManager`) causes a "Maximum call stack size exceeded" error. The original code in `getResponseTimeDistribution` failed on datasets of ~200,000 items. Additionally, chaining array methods (`.filter()`, `.map()`, `.reduce()`) as seen in `getSessionStats` is highly inefficient for large arrays, taking ~10x longer than a single-pass `for` loop.
**Action:** Replace `Math.max(...times)` with a single-pass `for` loop to find maximum values. For large data aggregation, avoid chaining array methods; instead, use a single `for` loop to accumulate multiple metrics simultaneously, eliminating intermediate array allocations and reducing CPU overhead. Use integer-indexed arrays for bucketing (bins) and map to string labels after the loop rather than using string interpolation and object properties inside the loop.
