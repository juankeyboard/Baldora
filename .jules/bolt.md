## 2024-05-24 - Maximum call stack size exceeded on large arrays
**Learning:** Using the spread operator with `Math.max(...array)` or `Math.min(...array)` is a critical performance bottleneck and anti-pattern in vanilla JS when dealing with large datasets (e.g., historical user session data in `DataManager.history` containing >100,000 items). It causes "Maximum call stack size exceeded" errors because JavaScript engines limit the number of arguments a function can accept (typically around 65,535). Furthermore, chaining multiple array methods (`.filter().map().reduce()`) over large sets drastically degrades performance and memory usage due to intermediate array allocations.
**Action:** Always replace chained array methods with a single-pass `for` loop, and explicitly calculate min/max inside the loop instead of relying on the spread operator. When counting/bucketing frequencies, use integer-indexed arrays inside the loop instead of string manipulation, resolving string labels only after the loop completes.
