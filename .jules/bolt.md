## 2024-05-24 - Maximum call stack size exceeded in array spread and bucketing performance
**Learning:** Using the spread operator (`...`) with functions like `Math.max` on large arrays (e.g., >100,000 items in `history` or `sessionData`) causes a "Maximum call stack size exceeded" error. Additionally, when processing large datasets, using object property assignment with string interpolation (e.g., `bins[\`${i}-${i+binSize}s\`] = 0`) is significantly slower than using integer-indexed arrays.
**Action:** Use a single-pass `for` loop to find extreme values (max/min) in large arrays instead of spread operators. For bucketing/histogram algorithms, use integer-indexed arrays inside the loop and map them to string labels after the loop completes to avoid string allocation and property lookup overhead.
