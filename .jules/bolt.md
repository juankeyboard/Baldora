## 2024-06-15 - Array Iteration Performance & Call Stack Limits in DataManager
**Learning:** In vanilla JS architectures with large datasets (like `history` or `sessionData` reaching 100k+ elements), chaining array methods (`.filter().map().reduce()`) creates significant CPU overhead and multiple intermediate array allocations. Further, using the spread operator (`...`) with `Math.max` or `Math.min` on large arrays causes 'Maximum call stack size exceeded' errors. String interpolation and object property lookups inside loops also cause significant bottlenecks for bucketing (e.g., histograms).
**Action:** Replace chained array methods with single-pass `for` loops. Avoid spread operator for extremes on large arrays. Use integer-indexed arrays for binning inside loops, and map to string labels only after the loop completes.
